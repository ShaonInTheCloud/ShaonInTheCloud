# VPN takeover guard and Storage guard — 17 October 2026 (lab 0.5.1-test)

Owner findings on the emulator (API 35) with SafeNest Test 0.5.0-test:

1. **App info › Storage** showed *Clear storage* / *Clear cache* and did not bounce. Clearing storage ends the commitment.
2. **1.1.1.1 (Cloudflare WARP)** could be installed from Play, granted VPN access and connected; it replaced SafeNest's VPN and every blocked site loaded again.
3. The **gear next to SafeNest Test in Settings › VPN** bounced to Home immediately, so Always-on VPN could never be switched on.

What changed

- `SystemScreenGuard`: Storage headings are page chrome; *Clear storage / Clear data / Clear cache* (EN/BN/FI) bounce on both guard paths.
- New `blocksForeignVpnConsent`: Android's `com.android.vpndialogs` "Connection request" prompt is refused (Back, then Home) for every app except SafeNest. This is the one gate every third-party VPN must pass, so it closes the takeover regardless of how the VPN app was installed. SafeNest's own prompt stays usable.
- `blocksVpnInstall` (Play Store install of a known VPN) now also runs in the lab build during a consented test, not only in the direct build.
- "Block detected VPN apps" now **defaults to on**; expiry resets it to the default instead of forcing it off.
- Own VPN detail page (`isOwnVpnDetail`) is **allowed**. While protection is committed the service switches *Always-on VPN* back on whenever it is found off (`ensureAlwaysOn`, ACTION_CLICK on the row's switch, 1.5 s cooldown). Only the *Forget* confirmation (`isForgetConfirmation`) and the Disconnect dialog bounce. The app-name window title alone no longer bounces, because App info and the VPN detail page share it.
- `SafeNestVpnService`: a takeover (`onRevoke` or the 2 s watchdog) during committed protection posts a high-importance "Protection interrupted — tap to restore" notification; `MainActivity` re-requests the VPN slot automatically the next time SafeNest is in front (once per visit), so one tap on OK restores protection.

Still true: without Device Owner this is an Accessibility barrier, not root. A VPN that was authorised **before** the test started will not show the Connection request again; the app itself is still bounced to Home when opened, and the restore prompt follows any takeover. The ownerlab build (always-on lockdown + `DISALLOW_CONFIG_VPN`) remains the only hard guarantee, and is the Play-launch recommendation.

Tests: `CommitmentGuardRegression` 89 checks (Storage page from the owner's screenshot, 1.1.1.1 connection request refused, SafeNest's own request allowed, own VPN detail open, Forget confirmation bounces, consumer-path equivalents).

## 0.5.2-test — actions, not pages (same day, after owner testing 0.5.1)

0.5.1 still bounced on the VPN gear (the "allowed" branch fell through to the generic Forget VPN
match) and on App info (the guard reacted to buttons being *present*). The owner's contract is now
explicit and the guard implements it:

- **Pages open freely**: App info, Storage, SafeNest's VPN detail, the VPN list, Settings home.
- **Taps bounce**: the accessibility service now receives `TYPE_VIEW_CLICKED`; a tap on Uninstall,
  Force stop, Clear storage/data/cache, Forget VPN, Disconnect, Disable (EN/BN/FI) *while SafeNest's
  own page was on screen in the last 20 s* goes Back + Home immediately (`destructive_tap`).
- **Confirmations bounce** as a second line: uninstall dialog (installer + app name + OK/Uninstall),
  "Force stop?", "Delete app data?", "Forget this VPN?", Disconnect — attributed to SafeNest via the
  same 20 s own-page memory, which is reset the moment another app's detail page is seen.
- **Always-on VPN**: on SafeNest's own VPN page the guard flips the switch back on whenever it is off.
- The own Accessibility detail page still bounces on entry: its switch is the one control that kills
  the guard before any dialog could be read.

`CommitmentGuardRegression` is at 110 checks; `GuardDeviceFlowTest` (CI emulator) now asserts the
page-open / tap-bounce contract including Storage and Forget VPN.

## 0.5.9-test — Always-on: guard the consequence

CI emulator trace (Android 16): on SafeNest's VPN detail page the service can read only the header
(5 labels); the Always-on / Block connections / Forget VPN rows are hidden from it, and after the
switch is toggled the whole window returns a null root. These rows are accessibility-data-sensitive,
which Android 14+ exposes only to services declaring `isAccessibilityTool=true`; Google states Play
rejects and Play Protect blocks apps that claim that flag without being an accessibility tool
(https://android-developers.googleblog.com/2025/12/enhancing-android-security-stop-malware.html).
SafeNest therefore does not claim it.

What the guard does instead: Android drops SafeNest's VPN ~250 ms after Always-on is switched off.
`SafeNestVpnService.onRevoke` (and the 2 s watchdog) now call
`SafeNestAccessibilityService.protectionRevoked`, which performs the same Back → Home exit as a
destructive tap, posts the "Protection interrupted — tap to restore" notification, and SafeNest
re-requests its VPN slot the moment it is in front. Forget VPN keeps bouncing through its
confirmation dialog, which is not sensitive. The hard guarantee that Always-on cannot be switched
off at all remains the device-owner build (`DISALLOW_CONFIG_VPN` + always-on lockdown).

## 0.5.11 — gambling apps, VPN browsers, full blocklist

- **Full bundled blocklist on Android:** the compact 541,485-name assets (`gambling_core.snbl`,
  `gambling_hagezi_gpl3.snbl`) from `launch/play-billing-and-full-guard` are ported to this branch
  (BundledGamblingRules, CompactDomainSet, tools/blocklist). The old 35k text assets are gone.
- **Gambling apps** (`AppBlockRules` + `BlockedAppCatalog`): opening one returns Home in every build while
  protection is on. Recognised by exact package ID, the app's reversed domain being on the gambling list
  (com.bet365.x → bet365.com; dream11.com is listed, so Dream11 is blocked), a gambling brand as a whole word
  of the package ID or app name, gambling words (casino, poker, slots, betting…), or -bet/bet- brand shapes
  with an exclusion list of ordinary words. Updatable lists: `assets/blocked_apps/gambling_packages.txt`,
  `gambling_app_brands.txt`.
- **Browsers with a built-in VPN/proxy** (Opera family, Aloha, Tor/Orbot, Puffin, Avast Secure, Tenta, Epic;
  `assets/blocked_apps/vpn_browsers.txt`) are blocked whole, like Gamban; their Play Store install page
  returns Home.
- **Address-bar check widened** to Chrome, Edge, Brave, Vivaldi, Kiwi, Samsung Internet, Firefox/Focus,
  DuckDuckGo, Mi and Yandex browsers, and now runs in the lab build too. The address bar shows the real site
  even when a browser's own VPN (e.g. Edge Secure Network) hides the traffic from the DNS filter.
- **Install guard:** Play Store / installer pages for gambling apps (brand or gambling word in the title)
  return Home.
- Tests: `AppBlockRulesRegression` (45 checks, incl. ordinary apps that must stay usable) in run-core-tests.sh.
- Not covered: a gambling app with an unknown package, unknown brand and no gambling word in its name —
  add it to `gambling_packages.txt`. Browsers not in either list fall back to the DNS filter only.
