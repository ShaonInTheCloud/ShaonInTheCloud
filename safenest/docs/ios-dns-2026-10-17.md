# SafeNest for iPhone — DNS profile (test), 2026-10-17

Expo Go cannot run blocking code, so iPhone blocking starts with an encrypted-DNS profile.

- `supabase/functions/dns-query` — RFC 8484 DoH filter. Blocks the bundled 35,155-domain list
  (`data/safenest-gambling-domains.txt`, regenerate with `node scripts/build-dns-domains.mjs`), the latest
  published blocklist when one exists, and common encrypted-DNS endpoints. Blocked A/AAAA → 0.0.0.0 / ::,
  other types → empty NOERROR. Everything else is forwarded to Cloudflare, then Google. No logging.
- `website/ios/safenest-dns.mobileconfig` — `com.apple.dnsSettings.managed` profile pointing at
  `https://kflenmeizngmafwnwhgv.supabase.co/functions/v1/dns-query` (regenerate with
  `node scripts/build-ios-dns-profile.mjs [url]`). Served as `application/x-apple-aspen-config`.
- `website/ios/` — install page. `cloudflare/dns/` — the same filter as a Worker for scale.
- Tests: `tests/dns-query.test.mjs` (wire format, matching, fallback, profile, config).

Deploy: `npx supabase functions deploy dns-query --project-ref kflenmeizngmafwnwhgv`
(or the "SafeNest deploy backend" workflow with `apply`). **Install the profile only after the
function answers** — a profile pointing at a missing endpoint breaks all DNS on the phone.

Limits: removable by the phone's owner; a connected VPN app overrides it; Edge Function quota
(500k/month free) suits testing only — move to the Worker or a dedicated resolver for users.
Real lock on iPhone = Screen Time API (Family Controls) in a native build; needs an Apple Developer account.
